### Decisions the owner must take before a plan can be written

1. **The AdSense script runs on the pages where keys are used.** `apps/web/src/app/layout.tsx:34-46` loads
   Google's script from the root layout, so also on `/spaces/…`, `/account` and the login pages, where the opened
   private key sits in `localStorage` (`apps/web/src/lib/spaces/key-session.ts`). ADR 0005 rests the site's
   promise on "the deployed code is public"; a script served by a third party is outside that.
   `docs/features/site-publicite.md` keeps the ad _slots_ off those pages, not the script. Moving the script
   into the ad slot is not enough: the site changes pages without reloading, so a script loaded on a guide is
   still there on `/spaces`. Real separation means full page loads into the private sections, or ads on
   another origin. It also touches the AdSense review under way. M, MED risk.
2. **One Joueur per server per account is assumed, not enforced.** `apps/web/src/server/reminders/prisma-store.ts:11`
   says it "cannot happen"; `DeclaredPlayer` (`apps/web/prisma/schema.prisma:247-265`) has no such constraint and
   `declarePlayer` (`apps/web/src/server/extension/extension-api.ts:121-132`) does not check. Several places take
   the account's first membership in a space (`apps/web/src/server/spaces/space-service.ts:135`), so a Délégué
   with a second Joueur in the same space could validate that Joueur's own Demande. Either forbid it (what
   about a player who restarts on the same server?) or make every action name its acting Joueur. Check
   production first: `SELECT "userId", server, count(*) FROM accounts.declared_player GROUP BY 1, 2 HAVING count(*) > 1`.
3. **The Envoi choices survive unlinking.** After « Déconnecter » and a new link — to another account too —
   the categories ticked before start sending again (`apps/extension/src/data/envois.ts:88-90` keeps
   `CHOICES_KEY`; `features/optizzz-account/envois.ts:627-631` even switches them back on site-side). Intended?
4. **How long `PlayerDay` is kept.** About 216 000 rows a night for S4 alone, never purged; the roadmap says the
   Journal is kept forever but says nothing of these rows. The answer shapes the performance work below.

## Findings considered and rejected

- **The flood plan's loop (`packages/game/src/flood.ts`) and the chain's (`apps/extension/src/features/tdc-chain/chain.ts`) differ.** They only split the last, ant-capped wave differently, and the total taken is the same. Merging them is not worth the risk.
- **O(M×P) scan in `apps/extension/src/features/alliance-stats/production.ts:118,129`.** It is about 600k comparisons for a large alliance, which is negligible.
- **627 KB of always-on CSS with images inlined (`game-look`).** The size is real, but its paint cost has not been measured. Measure it before planning anything.
- **`@vitest/coverage-v8` pinned exactly while `vitest` is a range.** Too minor to plan.
- **Storage race on `local:alerts:stocks` between two different servers.** Those are two origins, so Web Locks cannot help. The lost write only reverts that server's stock to its previous reading until its next page load. Recorded in plan 004.
- **(2026-11-12) The `/api/extension/*` route files have no tests of their own.** Each is 7–16 lines that delegate to a tested module (`extension-api.ts`, `envois/extension-routes.ts`, `demandes/extension-routes.ts`). Not worth it.
- **(2026-11-12) The revalidation secret is compared with `!==`** (`apps/web/src/app/api/revalidate/route.ts:6`). A timing attack over the network on a 16-character secret is impractical, and the only gain would be forcing a rebuild of the pages.
- **(2026-11-12) No alert when the cron fails.** Decided in ADR 0009 (`journalctl`, and the back office's `JobRun`).
- **(2026-11-12) The extension token never expires.** A recorded decision (`apps/web/prisma/schema.prisma:227-229`); it is revocable from the account page.
- **(2026-11-12) Two chart libraries on the site (ECharts and Recharts).** Deliberate: ECharts is shared with the extension through `packages/map`.
- **(2026-11-12) The large Space components of the site have no tests** (`demandes-panel.tsx`, `member-space.tsx`, `chain-panel.tsx`). Their rules already live in tested `apps/web/src/lib/`; what is left in the views is formatting.
- **(2026-11-12) `apps/web/AGENTS.md` addresses AI agents.** It is the note Next.js generates; nothing in it was acted on.
